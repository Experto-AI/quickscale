# Changelog

`CHANGELOG.md` is the canonical QuickScale release history index. Published releases pair each version entry with a single official release note in `docs/releases/` linked from the GitHub tag and release PR. When a release note is prepared before the maintainer completes the manual tag/publish step, the changelog entry and note must say so explicitly and must not imply publication. Use `docs/technical/roadmap.md` for active or unpublished release status. Entries are version-ordered.

- v0.87.0 — unreleased / not yet tagged — Hardening release (in progress). Consolidates a large hardening pass across tenant isolation, module configuration, the generator, and disaster recovery.
  - **SA7.1 — `organization_created` signal replaces CRM bootstrap reverse-import.** Defined and dispatched an `organization_created` Django signal from `OrgCreateForm.save()` in the orgs module. Added a CRM-side receiver (`seed_crm_default_stages_on_org_created`) connected via `QuickscaleCrmConfig.ready()` that calls `ensure_org_default_stages`. Deleted the `crm_bootstrap.maybe_seed_crm_default_stages` reverse-import bridge (`crm_bootstrap.py`). The personal-org creation path (`create_personal_for`) is unchanged — no signal is fired from the manager. CRM view-level warm-on-read bootstrap in `crm/views.py` remains untouched. Acceptance: org creation still seeds CRM default stages when CRM is installed, orgs now contain zero CRM-specific code.
  - **SA7.2 — Fail-hard the auth-adapter import fallback.** Replaced the silent `try/except ImportError` fallback in `orgs/adapters.py` with an unconditional import from `quickscale_modules_auth.adapters.QuickscaleAccountAdapter`. If the auth module is not on the Python path, the `ImportError` now propagates as a hard failure at module load time instead of silently degrading to `DefaultAccountAdapter`. The auth module is always importable via PYTHONPATH without Django app registration, so no `INSTALLED_APPS` change was needed. Declared `required_modules: [auth]` in both orgs module manifests (module-owned and core data mirror), and added `quickscale-module-auth = ">=0.71.0,<0.87.0"` to `orgs/pyproject.toml` so the metadata matches the unconditional import. The `implies` section was intentionally left unchanged — auth is gated by the apply-time prerequisite check (`_validate_module_prerequisites`) rather than auto-resolved via implications, so users must explicitly include the auth module. Closes the known fail-hard violation tracked in `decisions.md` §fail-hard-principle and resolves `CR-SA7.2-001`.
  - **SA7.3 — De-duplicate notifications defaults out of orgs' manifest.** Removed the inlined `default_config` block for notifications from `orgs/module.yml`'s `implies:` section (both module-owned and core data mirror). The notifications module's own canonical `module.yml` config defaults are now the sole source of truth. Updated the `test_orgs_implies_notifications_default_config_parity` drift-prevention test to assert the implied `default_config` is empty, preventing re-duplication. Updated all implication tests to expect empty config dicts for the notifications implication. Behavior preserved: both the old inline defaults and the canonical notifications defaults were identical, and the downstream apply/plan flow falls through to notifications' own manifest defaults when the implied config is empty.
  - **SA11.1 — Orgs-owned public-read context helper (complete).** `quickscale_modules_orgs.public_context` with `resolve_public_org_context()` context manager (primes tenant ContextVar/GUC for a given org or the System org singleton) and `PublicSystemOrgReadMixin` CBV seam (wraps dispatch in `org_scope()` for automatic tenant-context isolation). 18 unit tests covering org resolution, real tenant-scoped queries, fail-closed no-org path, mixin dispatch lifecycle, and TemplateResponse render lifecycle — including `test_mixin_forces_template_response_render` that proves lazy queryset evaluation during template rendering sees the primed tenant GUC (strengthened in CR-SA11.1-003 to use a lazy `QuerySet` instead of an eagerly-evaluated `count()`). The `.render()`-forcing fix in `dispatch()` resolves the CR-SA11.1-001 design gap for template-backed generic views (`ListView`/`DetailView`), so SA11.3/SA11.4 can now consume the helper. See `docs/technical/roadmap.md` §SA11.1 for the full closeout status.
  - **Billing ledger idempotency, DB-enforced.** Added a partial unique constraint on `CreditTransaction.(stripe_event_id, transaction_type)` when `stripe_event_id` is populated. `credit_user` now catches `IntegrityError` from concurrent duplicate inserts and returns the existing row, adding a database-level backstop to the existing procedural `_find_existing_credit_transaction` dedup. (SA12.1)
  - **SA9.2 — Module-vs-oldest-claimed-core compatibility check (completed).** Added `scripts/check_module_core_compatibility.py` — a two-phase script that (1) statically analyses each module's `quickscale_core` imports against the on-disk core source, and (2) performs a real install/import probe: for each module with a quantifiable minimum core version, creates an isolated venv, installs `quickscale-core==<min_claimed>` plus the module's non-core deps from PyPI, and imports the module's package plus its `services` submodule and all management command modules. Wired as `make check-core-compat` (step 3 in `scripts/check_ci_locally.sh`, included in `make check`). Added a `module-core-compat` gate job in `.github/workflows/ci.yml` that the `test` CI job depends on. Pass `--skip-install-probe` to skip the heavy runtime check for local development. SA9.2-FINDING-001 (embedded manifest drift) remains advisory and non-blocking.
    - **Backups-only skip mechanism:** Added `SKIP_INSTALL_PROBE_MODULES` — a dict constant keyed by module name with a documented reason string citing the confirmed 2026-07-03 roadmap decision. The install/import probe is skipped for `backups` only (pre-existing version mismatch: no published `quickscale-core>=0.86.0,<0.87.0` contains `quickscale_core.dr_engine`, which backups requires). Static analysis (Phase 1) still runs for all modules. Test-enforced: the test asserts only `backups` is in the dict and the reason is dated.
    - **Management-command probe coverage (CR-SA9.2-002):** Added `_get_management_command_modules()` helper that discovers `management/commands/*.py` modules per module. Extended `_build_probe_script()` with Phase 3 that imports each discovered management command using the same `quickscale_core`-aware failure heuristic as Phase 2b.
    - **Tests:** Created `test_check_module_core_compatibility.py` with 12 tests covering skip-allowlist integrity, management command discovery (backups=9+, forms=2, crm=0), probe code generation, and public symbol regression.
  - **SA9.3 — `quickscale_core.runtime` public facade (completed).** Created `quickscale_core/src/quickscale_core/runtime.py` — a pure re-export layer covering the DR adapter surface (`capture_snapshot`, `fetch_snapshot_report`, `record_verification`, `set_rollback_pin`, `build_database_plan`, `execute_database_restore`, `sync_media`, `ADAPTER_FUNCTIONS`, and `BackupError`) plus the social-manifest rendering surface (`SOCIAL_LINK_TREE_PATH`, `SOCIAL_EMBEDS_PATH`, `SOCIAL_INTEGRATION_BASE_PATH`, `SOCIAL_INTEGRATION_EMBEDS_PATH`, `resolve_social_module_options`, `assemble_wiring_spec`, `ResolverResult`, `load_social_manifest`, `render_social_managed_init_module`, `render_social_managed_urls_module`, `render_social_managed_views_module`, `social_provider_supports_embeds`, and `ModuleWiringSpec`). Includes focused direct tests in `quickscale_core/tests/test_runtime.py` that verify every symbol is importable, correctly typed, and matches the `__all__` export list. No existing import paths removed (that's SA9.4/SA9.5).
  - **Compatible-range pin for backups' core dependency (SA9.1).** Narrowed `quickscale-core>=0.86.0` to `>=0.86.0,<0.87.0` in `backups/module.yml`. Updated `sync_project_module_dependencies` to fall back to the manifest version spec when the module's `pyproject.toml` declares a non-string (path) dependency, so generated projects receive a bounded version range. Wired `_sync_module_dependencies` into the module update flow so `quickscale update` refreshes generated-project dependencies after subtree pull.
  >   **Follow-up fix (SA9.1-REV-004):** Update-time shared-dependency repinning is now order-independent. When multiple installed modules (e.g., storage + backups) declare the same third-party dependency, `sync_project_module_dependencies` uses `_prefer_dependency_value` to select the highest compatible version floor across all modules before overwriting project pins. The update path now passes all installed modules' options to the resolver so shared dependencies consider the full installed module set. Added regression tests for storage+backups cross-module repinning in both table-form and plain-string pyproject entry shapes.
  - **Tenant isolation, unified and enforced everywhere.** Every tenant-scoped model (CRM, blog, forms, listings, social, billing) now inherits from a single shared base class instead of hand-copying its data-isolation boilerplate, removing the main source of drift between modules. A new isolation check runs automatically across the *entire* project — not just QuickScale's own modules — and every model must be explicitly registered as either tenant-scoped or intentionally excluded, so nothing can silently fall through the cracks. That same check is now wired into the CI pipeline of projects generated by `quickscale apply`, so isolation is verified in the customer's own generated app, not just in this repo.
  - **Fail-closed database access.** The app now refuses to boot if it's connected to the database under a role that bypasses row-level security, unless an explicit override is set — this used to fail silently in some configurations. Production settings likewise require a restricted, tenant-safe database role by default, with the elevated role reserved only for running migrations.
  - **Documentation kept honest.** The architecture docs describing the tenant-isolation contract were resynced with what's actually shipped (they'd drifted), and a CI check now fails the build automatically if the docs and the code disagree again in the future.
  - **Reduced per-request database overhead.** Tenant-context setup within a single database transaction is no longer repeated redundantly for every statement.
  - **Declarative module configuration, piloted.** The analytics module now derives its configuration entirely from its manifest file instead of hand-written Python glue code — proving out a simpler path for configuring modules. A guardrail now blocks any new module from reintroducing the old hand-written approach.
  - **`module.yml` derivation YAML loader (SA6.1).** The deferred YAML loader wiring for `ModuleDerivationSchema` is now proven by a full round-trip test: a `module.yml` with a `derivation:` section covering all seven field categories (normalization_rules, validation_rules, legacy_aliases, module-level derived_settings, per-option derived_settings, wiring_projections, option_derivations) parses through `load_manifest` and `build_schema_from_manifest` into a typed `ModuleDerivationSchema` equal to a directly-constructed hand-built schema. Module-level `derived_settings` are now preserved in the typed schema via a new `shared_derived_settings` field on `ModuleDerivationSchema` and correctly wired through `build_schema_from_manifest()`. The round-trip test uses directly-constructed dataclasses for the hand-built reference to eliminate shared-helper bias. No runtime behavior change.
  - **Listings module fully migrated to declarative derivation (SA6.2).** Listings' defaults, normalization, and validation now come from `module.yml`'s `derivation:` section instead of hand-written Python. The imperative `_build_listings_derivation_schema`, `default_/normalize_/resolve_/validate_listings_module_options` functions in `resolvers.py` and the configurator triad (`get_default_/configure_/apply_listings_configuration`) in `module_config.py` have been removed. `LISTINGS_MANIFEST` in `imperative_inventory.py` is cleared to `[]`, matching the analytics precedent. The manifest adapter in `entry_point.py` (already core-inline) now sources its schema from the loaded manifest. Listings also gained a `required_modules: [orgs]` declaration and an `implies: [{name: orgs}]` block so the planner implication resolver auto-materializes orgs when listings is selected (fixes SA6.2-CR-001). Preserves existing `quickscale plan --add listings` + `quickscale apply` behavior.
  - **Imperative-wiring freeze guardrail extended for listings (SA6.3).** Added a dedicated test asserting `get_manifest_inventory("listings")` returns `[]`, matching the existing analytics guardrail. Re-introducing imperative listings builder entries will now fail CI.
  - **Operator tooling.** Admins can now temporarily "view as" a specific organization from the admin panel to debug issues in context, with a visible banner while active and a one-click exit. Separately, sensitive maintenance commands (like purging an organization) now go through a single, audited access path that logs who ran what and why.
  - **More resilient project generation.** Running `quickscale apply` now checkpoints progress after each step, so a failed run can resume where it left off instead of starting over. Destructive or remote actions (starting containers, running migrations, deploying) require explicit confirmation before proceeding. The generator's internals were also reorganized into smaller, focused modules for maintainability.
  - **Stronger database-level safeguards.** Parent/child record relationships (e.g. a CRM contact and its notes) are now enforced to stay within the same organization at the database constraint level, replacing a more fragile trigger-based check. A row-level-security policy bug affecting pooled database connections was also fixed.
  - **Test infrastructure simplified.** All modules now test exclusively against PostgreSQL (the only database QuickScale actually supports in production); the SQLite test fallback was removed everywhere. A dedicated CI job proves tenant isolation holds under a real restricted database role, and is structured so it cannot pass by silently skipping.
  - **Billing ownership clarified.** Subscriptions are now authoritatively owned by the organization rather than the individual user who created them.
  - This release also carries the tenant isolation, single-URL routing, module-manifest wiring, and disaster-recovery rework that was the original scope for this cycle, plus the hardening items above added after a mid-cycle architecture review.
