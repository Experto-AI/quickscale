# Changelog

`CHANGELOG.md` is the canonical QuickScale release history index. Published releases pair each version entry with a single official release note in `docs/releases/` linked from the GitHub tag and release PR. When a release note is prepared before the maintainer completes the manual tag/publish step, the changelog entry and note must say so explicitly and must not imply publication. Use `docs/technical/roadmap.md` for active or unpublished release status. Entries are version-ordered.

- v0.87.0 — unreleased / not yet tagged — Hardening release (in progress). Consolidates a large hardening pass across tenant isolation, module configuration, the generator, and disaster recovery.
  - **SA26 — Sanitize markdown-rendered URI schemes on public blog/listing detail pages.** `markdownify(escape(...))` blocked raw HTML injection but not markdown-native `[text](javascript:...)` links, which rendered as an unescaped `<a href="javascript:...">` under the `|safe` filter. Added a stdlib-only `_sanitize_rendered_html()` helper to both `blog/views.py` and `listings/views.py` that runs the rendered markdown HTML through an allowlist URI-scheme check before it reaches the `|safe` filter. The helper uses `re.sub` to inspect every `<a href="...">` attribute: `http:`, `https:`, `mailto:`, relative URLs, protocol-relative URLs, and fragment-only links are preserved; all other schemes (`javascript:`, `data:`, `vbscript:`, …) are neutralised by replacing the href with an empty string. No new dependency added. Added 3 focused regressions per module (6 total) proving javascript links are neutralized, https links remain clickable, and mailto links remain clickable — on both blog PostDetailView and listings ListingDetailView.
  - **SA40 — Reject non-string values on public form submit instead of 500ing.** Hardened `FormSubmissionCreateSerializer` so public form submissions now reject non-string values with explicit validation errors and no runtime 500s. `None` still follows required-field semantics, while invalid scalar/container types now surface `This field must be text.` for affected fields. Added integer parsing/validation for `min_length` and `max_length` rule settings in form validators so malformed rule config returns `ValidationError` (for example, `Validation rule 'min_length' must be a whole number`) instead of crashing during validation. Added serializer/view regression coverage for non-string payloads and invalid validation-rule config. Closes SA40.
