# Contributing to QuickScale

1. Set up the environment: [development.md](../technical/development.md).
2. Learn the binding rules: [rules.md](rules.md) for engineering, and
   [decisions.md](../technical/decisions.md) for repo-wide policy and scope.
3. Use the stage guide that matches the work. Guides apply the rules and add repo commands
   and checklists. They set no required order, and they never override `rules.md`.
   - [plan.md](plan.md): scope, affected areas, approach
   - [code.md](code.md): implementing inside an approved boundary
   - [review.md](review.md): reviewing plans, code, tests, docs
   - [testing.md](testing.md): test locations, categories, commands
   - [debug.md](debug.md): diagnosis and root-cause fixes
4. Find open work in [roadmap.md](../technical/roadmap.md). Validate with the entrypoints in
   [validation_policy.md](../technical/validation_policy.md).
5. Releases follow [publish_procedure.md](../technical/publish_procedure.md).
